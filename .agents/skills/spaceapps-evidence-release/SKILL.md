## Server delivery

Every server handoff must be **one complete .zip** containing all required code, built static assets, dependency locks, runtime/process/container settings, necessary lawful data/calibration or exact existing-volume contract, source/license notices, start/deploy/health/rollback instructions and release_manifest.json.

Exclude local.env, credentials/private keys/cookies, private team documents, .git, caches/logs and irrelevant development artifacts. Supply safe configuration examples and precise required setup. Do not silently overwrite persistent observations/evidence/DB volumes.

Build from a known working tree/release identity and record whether it has uncommitted changes. Use the actual selected versions. Extract the archive into a clean directory, check relative paths/case and start instructions, run the meaningful runtime/health/representative-flow checks supported by that release, and compare file hashes/required data. Do not invent a commit or claim a Linux/container run that did not occur.

Record archive filename/bytes/SHA256, included file hashes, build/test times and commands, source/data/model versions, verification limits and deployment/rollback steps. Provide the actual absolute ZIP link to the user. If the app is not runnable yet, report the development state rather than generating an empty deployment ZIP.
