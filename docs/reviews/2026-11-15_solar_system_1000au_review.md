## 1. 방향과 구현 가능한 목표

태양계에 집중하는 방향은 SPHEREx + Planet X라는 주제에 더 잘 맞는다. 다만 목표를 다음처럼 구체화해야 구현 가능성과 과학적 신뢰성을 함께 지킬 수 있다.

> 태양에서 1,000 AU까지를 주요 탐색 범위로 삼아, 알려진 태양계 천체의 관측·궤도·물리량을 연결하고, 제9행성 가정이 만드는 예측을 실제 SPHEREx 관측과 비교하는 도구.

**그 안의 모든 천체와 모든 물리를 실제 그대로 완벽히 복제한다는 보장은 할 수 없다.** 아직 발견하지 못한 천체, 측정되지 않은 질량·내부 구조, 불확실한 초기조건은 계산만으로 확정할 수 없기 때문이다.

대신 무엇이 관측값이고, 무엇이 추정·가정이며, 어느 정확도까지 검증됐는지를 명확하게 관리한다.

### 1.1 문제의식과 사회적 가치

당장 생활에 주는 직접적인 이득보다 **태양계의 구조와 형성 과정을 더 정확히 이해하는 것**을 과학적 목표로 삼는다.

- 해왕성 너머 천체들의 특이한 궤도를 설명하는 가설을 비교한다.
- 제9행성이 존재한다면 외곽에 자리 잡게 된 과정과 초기 행성 이동 역사를 조사할 수 있다.
- 태양계에 관한 결과는 다른 행성계의 형성과 구조를 이해하는 연구에도 연결될 수 있다. 이를 위해 외계행성 도감을 제품 안에 유지할 필요는 없다.

다만 앱이 당장 입증할 수 있는 기여는 **분산된 자료 접근, 가설 비교, 불확실성 이해, 재현 가능한 근거 정리**다. 제9행성 발견이나 태양계 형성 과정의 복원 성공까지 보장해서는 안 된다.

근거: [NASA Planet X](https://science.nasa.gov/solar-system/planet-x/), [Caltech 연구 설명](https://www.caltech.edu/about/news/caltech-researchers-find-evidence-real-ninth-planet-49523).

따라서 향후에는 **태양계 기능이 실제로 사용하는 자료만 따라가는 의존성 목록**으로 바꿔야 한다. 화면·숨은 진입·API·자료 내보내기·정적 빌드·ZIP·검사 계약을 함께 정리한다.

기존 v0.11 ZIP과 Git 이력은 보존하고, 새 제품과 새 배포본에서 삭제 기능을 제외한다. 원본 자료를 대량 폐기할 이유는 없다.

## 4. 1,000 AU의 정의와 목록 완전성

### 4.1 800 AU는 확정된 현재 위치가 아니다

제9행성이 현재 정확히 800 AU에 있다고 확인된 것은 아니다. 2019년 원저자 검토의 400–800 AU는 **반장축 범위**였고, 2021년 연구에서는 다른 범위를 제시했다. 제9행성 자체도 아직 미발견 가설이다.

근거: [NASA 설명](https://science.nasa.gov/solar-system/planet-x/), [2019년 검토](https://arxiv.org/abs/1902.10103), [2021년 연구](https://arxiv.org/abs/2108.09868).

천체마다 다음 값을 구분한다.

- **현재 거리 r:** 선택한 시각의 태양과의 거리
- **반장축 a:** 타원의 크기를 나타내는 긴반지름
- **근일점 q:** 태양에 가장 가까워지는 거리
- **원일점 Q = a(1 + e):** 가장 멀어지는 거리

권하는 기본 규칙은 **선택 시각의 태양중심 거리 1,000 AU 이내를 주요 탐색 영역으로 삼는 것**이다. 다만 경계를 넘는 궤도도 계속 보관해야 한다.

천체가 1,000 AU를 넘었다고 삭제하거나, 중력을 끄거나, 경계에서 튕기게 만들면 실제 물리가 아니다. **1,000 AU는 화면과 연구의 범위이지 우주의 벽이 아니다.**

### 4.2 ‘모든 천체’의 구분

| 구분 | 처리 |
| --- | --- |
| 공식 행성·왜소행성 | 공식 분류와 출처를 유지 |
| 알려진 TNO·소행성·혜성·위성 | 채택 목록과 지원 상태에 따라 제공 |
| 왜소행성 후보 | 후보임을 유지하고 구형성·질량의 불확실성을 표시 |
| 제9행성 등 미발견 가설 | 관측 천체와 다른 표시·ID·상태로 관리 |
| 아직 알려지지 않은 천체 | 실제 존재 목록처럼 생성하지 않음 |

JPL SBDB는 알려진 소천체의 궤도와 일부 물리량을 제공하지만, 모든 천체의 질량·직경·공분산이 확보되어 있다는 뜻은 아니다. **누락은 미상으로 유지한다.**

근거: [JPL SBDB](https://ssd-api.jpl.nasa.gov/doc/sbdb.html).

## 5. 행성 3요건과 분류 실험

### 5.1 공식 분류와 사용자 기준을 분리

명왕성은 2006년 IAU 정의에 따라 왜소행성으로 재분류됐다. 질량이나 궤도가 그때 갑자기 바뀐 것은 아니다.

- 두 번째 조건은 **완벽한 구형**이 아니라, 자체 중력이 강체력을 이겨 **거의 둥근 정수압평형 형태**를 이루는 것이다.
- 세 번째 조건은 **주변 잔해가 전혀 없거나 모든 천체가 위성이 되었다는 뜻**이 아니다. 궤도 주변의 동역학적 지배력을 뜻한다.

근거: [IAU 원결의](https://www.iau.org/IAU/Iau/News/PR2006/iau-2006-general-assembly-resolution-votes.aspx).

사용자가 다른 정의를 시험하는 기능은 만들 수 있다. 화면에서는 다음을 나란히 보여준다.

| 표시 | 의미 |
| --- | --- |
| 공식 분류 | 채택한 IAU 기준의 현재 분류 |
| 관측된 물리량 | 출처가 있는 질량·크기·궤도·형태 |
| 사용자 분류 결과 | 사용자가 선택한 기준을 적용한 결과 |
| 판정 유보 | 필요한 자료가 부족해 결론을 내릴 수 없음 |

**규칙을 바꿔 분류가 달라지는 것과 보이지 않던 천체를 발견하는 것은 별개의 성과다.** 현행 기준에서 8행성이 행성이라는 분류와, 다른 기준을 적용했을 때의 결과를 혼동하지 않는다.

### 5.2 최소 질량의 정확한 의미

현재 채택한 태양 조건의 참고식은 다음과 같다.

```text
m_clear / M⊕ ≈ 0.001239 × (a / AU)^(9/8)
```

이 식은 태양 질량·청소시간 10 Gyr 등 조건을 고정한 **궤도 청소 모형의 참고 임계질량**이다. IAU의 공식 수치 규칙이나 모든 궤도에 적용되는 정확한 경계가 아니다. 원저자도 원궤도 근사와 고이심률 궤도의 한계를 명시한다.

근거: [Margot 등의 원논문](https://arxiv.org/html/2407.07590v1).

예를 들어 이 조건에서 **반장축 a = 1,000 AU**를 대입하면 약 **2.94 지구질량**이다. 이것이 ‘현재 1,000 AU에 있는 천체는 반드시 이 질량이어야 행성이 된다’는 뜻은 아니다.

정보창은 다음 구성이 적절하다.

> 세 번째 요건: 궤도 주변 지배력 — 자료 부족  
> 모형 임계질량: X M⊕ — 태양·10 Gyr·원궤도 참고  
> 본체 질량: 미측정  
> 가정질량 ≈ Y M⊕ — 선택한 밀도·반지름 가정

밀도와 반지름으로 계산한 질량은 사용할 수 있지만, **실측 질량으로 취급해서는 안 된다.** 비슷한 위성의 밀도를 가져오는 것도 비교 가정이며, 실제 동역학에서는 그 가정에 따른 결과 차이를 보여줘야 한다.

## 6. 필요한 물리 효과와 계산 범위

제9행성 연구에서 우선 필요한 것은 여러 물리 분야를 한꺼번에 넣는 것보다 **중력 동역학과 관측 기하를 정확하게 연결하는 것**이다.

| 물리·계산 | 반영 방향 | 구현 판단 |
| --- | --- | --- |
| 뉴턴 다체 중력 | 태양·주요 행성·선택한 질량 보유 천체의 상호작용 | 우선 구현 가능 |
| 소천체 운동 | 질량 미확보 천체는 시험입자 근사로 다수 계산 | 가능, 계산 역할과 미상 질량 구분 필요 |
| 제9행성 섭동 | 동일 초기조건에서 포함·미포함 계산 비교 | 가능 |
| 실제 관측자 위치·시차·광행시간 | 지구 또는 SPHEREx에서 보이는 방향 계산 | 관측 연결에 필수 |
| 태양계의 약한 상대론 보정 | 요구 정확도에 따라 검증된 보정 적용 | 가능하지만 별도 검증 필요 |
| 행성 비구형 중력·조석 | 위성·근접 궤도·장기 변화에 필요한 경우 적용 | 측정값과 목적에 따라 단계적 반영 |
| 혜성 비중력 가속도·복사압 등 | 해당 천체·입자에 필요한 항만 적용 | 입력 자료가 있을 때 조건부 가능 |
| 표면·반사·열 방출 | 관측된 제약과 가정한 모형으로 예측 | 가능하지만 실제 표면 복원과 구분 |
| 전체 양자·전자기·유체·내부 구조 결합 | 모든 천체를 미시적으로 계산 | 현재 목표로 보장 불가 |
| 태양계 탄생의 유일한 실제 역사 복원 | 현재 상태에서 과거를 완벽히 역산 | 보장 불가 |

구현할 때 중요한 조건은 다음과 같다.

- **화면 좌표로 중력을 계산하지 않는다.** 거리 압축·확대된 표시 반지름과 실제 AU·GM·시간을 분리한다.
- 질량중심 관성계 등 일관된 기준계를 쓰고 초기 위치·속도의 epoch를 통일한다.
- 지구·달을 따로 계산하면서 지구–달 질량중심의 계질량까지 중복해서 넣지 않는다.
- 질량이 미상인 시험입자는 ‘실제 질량 0’이 아니라 **중력 반작용을 생략한 계산 근사**다.
- 현재의 12물체 교육용 충돌 엔진을 이름만 바꿔 정밀 태양계 엔진으로 사용하지 않는다.
- 장기 안정성에 적합한 적분기와 근접 통과용 방법을 검토하고, 간격을 줄였을 때 결과가 수렴하는지 검사한다.

근거: [고정밀 적분기 연구 예시](https://arxiv.org/abs/1409.4779).

**재생 배속과 적분 간격은 다르다.** 화면에서 100년/초로 재생한다고 계산 간격까지 크게 늘리면 위성 궤도나 근접 통과를 놓칠 수 있다. 긴 계산은 미리 수행한 궤적을 재생하거나 별도 작업으로 처리해야 한다.

## 7. 실제 천체력 재현과 가설 시뮬레이션의 분리

| 모드 | 역할 |
| --- | --- |
| 관측·천체력 기준 | 채택한 JPL 위치와 실제 자료를 보여줌 |
| 제9행성 가설 | 같은 초기조건을 두 벌 만들어 제9행성 없음/있음을 비교 |
| 장기 통계 실험 | 초기조건·불확실성을 바꾼 여러 계산에서 가능한 궤도 변화·안정성을 비교 |

기존 JPL 위치를 매 순간 강제로 따라가게 하면서 제9행성의 힘만 추가하면, 태양계 전체가 서로 반응하는 새로운 다체 해를 계산한 것이 아니다. 시험입자 모형으로는 사용할 수 있지만 그 한계를 표시해야 한다.

가설 입력은 우선 질량, 기준시각, 위치·속도 또는 궤도요소로 구성한다. 주기와 반장축을 서로 모순되게 독립 입력하지 않고 선택한 중력 조건에서 일관되게 계산한다.

기존 Planet Nine 문헌 표본은 **가상의 궤도 표본**이다. 실제 행성 목록이 아니며, 2018년 기준 자료를 검증 없이 현재 위치 분포로 표시하면 안 된다. 사용자가 한 가설을 바꿨다고 문헌 분포까지 자동 재추론한 것처럼 바꾸지도 않는다.

태양계 형성 연구와 연결하려면 장기간의 가능한 경로를 비교해야 하지만, 그 결과를 **실제 탄생 장면의 재생**이라고 설명해서는 안 된다.

## 8. SPHEREx 관측과의 연결

### 8.1 새 대표 흐름

**태양계 천체 선택 → 물리량·불확도 확인 → 제9행성 가정 → 예측 하늘 경로 → 실제 SPHEREx 노출 → 품질·신호 검토 → 근거 저장·복원**

공식 IRSA의 **MOST는 SPHEREx를 지원하며, 사용자 궤도요소로 해당 예상 위치를 덮는 노출을 찾을 수 있다.** 따라서 가설과 실제 관측을 연결할 현실적인 경로가 있다. 다만 v0.11 앱에는 이 연결이 아직 구현되지 않았다.

근거: [MOST 공식 API](https://irsa.ipac.caltech.edu/applications/MOST/MOSTProgramInterface.html).

### 8.2 구분해야 할 검증 단계

- 예상 위치를 촬영한 영상이 있음
- 영상에 유효한 신호가 있음
- 그 신호가 해당 천체와 연관됨
- 실제 운동이 검증됨
- 새로운 천체의 궤도·정체가 확인됨

이 단계들은 서로 다르다. `SOURCE` 플래그나 예상 위치 근처의 밝은 점만으로 발견을 확정하지 않는다.

관측 연결에는 다음이 필요하다.

1. 실제 노출 목록·시각·검출기·파장·coverage 조회
2. SPHEREx 관측자 위치와 광행시간을 맞춘 예측
3. 영상 WCS에 대한 위치 투영
4. FLAGS·분산·배경·PSF·혼합 광원 확인
5. 기준별 정합과 위치 오차 검증
6. 다른 노출·알려진 소천체와 교차 확인
7. 입력·가정·원본 해시·판단을 함께 저장

### 8.3 거리와 검출 가능성

거리 1,000 AU의 단순 규모 계산만 해도 빛이 오는 데 약 **5.78일**이 걸린다. 1 AU의 횡방향 관측 기준선에 따른 시차 규모도 약 **206초각**이다. 이는 실제 검출 예측이 아니지만, 멀리 있는 천체일수록 **관측자와 시각을 맞추는 작업이 중요하다**는 것을 보여준다.

SPHEREx는 약 **0.75–5 μm**를 관측한다. 전천을 관측한다는 것이 그 안의 모든 거리·밝기 천체를 검출한다는 뜻은 아니다.

근거: [IRSA 기기 설명](https://irsa.ipac.caltech.edu/Missions/spherex.html).

반대로 차가운 천체라는 이유만으로 근적외선에서 무조건 보이지 않는다고 단정해서도 안 된다. 대기·내부열·반사 특성에 따라 스펙트럼이 달라지므로 실제 채널 응답과 잡음으로 검토해야 한다.

근거: [Planet Nine 대기·검출 가능성 연구](https://arxiv.org/abs/1604.07424).

**관측이 없거나 신호가 안 보인다는 사실을 ‘행성이 없다’로 바꾸지 않는다.**

## 9. Node.js 운영 구조

Node.js만 실행 가능한 환경에서도 선택한 다체 계산과 작업·저장 관리는 구현할 수 있다. 다만 현재 서버는 **두 FITS 관측 쌍의 빌드 결과를 검증해 제공하는 구조**다. 임의 천체·좌표·날짜의 FITS를 새로 분석하는 기능은 아니다.

현실적인 구조는 다음과 같다.

- Node 서버: 자료 검색·검증·작업 상태·캐시·근거 저장
- 별도 계산 worker: 태양계 가설 적분
- 기존 개발 환경의 과학 코드: 검증된 FITS·보정·WCS 산출물 준비
- 브라우저: 표시·선택·재생·가설 비교

현재 원본 검증 worker에 긴 동역학 계산까지 몰아넣으면 관측 저장과 응답이 막힐 수 있으므로 분리해야 한다. 임의 FITS의 즉시 정량 처리는 새로운 검증 경로가 필요한 별도 단계다.

많은 천체를 표시하더라도 방문자마다 모든 JPL 위치를 조회하지 않는다. 기준일 목록과 캐시를 사용하고 필요한 대상·기간만 조회하는 방식으로 설계한다.

## 10. 태양계에 집중한 화면 구성

상단은 다음 정도로 줄일 수 있다.

**탐색 · 실제 관측 · 제9행성 가설 · 비교/근거**

태양계 화면에는 다음을 배치한다.

- 행성·왜소행성·후보·TNO·혜성·위성 검색/필터
- 현재 태양 거리와 1,000 AU 범위 표시
- 선택 천체의 물리량·출처·자료 부족 상태
- 행성 3요건과 모형 임계질량
- 실제 관측 진입
- 하단 모형 시간과 적용 중인 자료·계산 방식

선택했을 때 천체 자체가 커지는 방식은 계속 피하고 **카메라가 다가가도록 유지**한다. 실제 비율 표시와 보기 위한 확대 표식을 구별하며, 둘 중 어떤 표시를 쓰더라도 물리 계산값은 같아야 한다.

특정 날짜에서 위치 지원이 없는 천체는 목록에서 사라지게 하거나 이전 위치를 새 날짜의 위치로 보여주지 않는다. **‘해당 시각 위치 미지원’**이라고 표시한다.

## 11. 기존 근거 복원과 이행

현재 근거에는 사용자가 은하를 열지 않았더라도 은하 자료의 해시가 포함될 수 있다. 이를 단순 삭제하면 정상적인 명왕성 근거까지 자료 변경으로 오판할 위험이 있다.

새 버전은 다음을 분리해야 한다.

- 원관측·비교 결과·판단의 무결성
- 제거된 기능의 옛 화면 상태
- 새 태양계 화면으로 복원할 수 있는 부분

관측 데이터가 그대로라면 **‘관측 재계산 필요’ 대신 ‘이전 화면 일부 복원 불가’**로 알려야 한다. 원 JSON·판단·비교 ID를 조용히 바꾸면 안 된다. 기존 v0.11 ZIP과 Git 이력도 보존한다.

## 12. 향후 구현 순서와 완료 기준

다음은 실행을 시작할 때의 제안 순서이며 이번 문서화에서 수행한 작업이 아니다.

1. 새 범위와 정확도·지원기간·데이터 상태를 FSD에 확정
2. 삭제 기능의 화면·숨은 진입·API·배포 의존성을 함께 정리
3. 현재 태양계·원지도·명왕성 관측·근거 복원 보존
4. 출처가 고정된 외곽 천체 목록과 불확실성 확장
5. 제한된 제9행성 포함/미포함 동역학 구현·검산
6. 예측 경로와 실제 SPHEREx 노출 연결
7. 검증 범위에 맞는 신호·운동 검토와 근거 저장
8. 새 완결 ZIP의 실행·재시작·복원 검사

완료 판단은 ‘천체가 많이 보인다’가 아니라 다음으로 내린다.

- JPL 기준과의 비교
- 적분 간격 세분화에 따른 수렴
- 조건에 맞는 보존량 진단
- 관측자·시각·기준계에 맞춘 투영
- 원관측 품질과 신호 검증
- 근거의 재현·새 세션 복원

## 13. 블랙홀 제외 사유의 과학적 표현

블랙홀 제외는 **주제 집중과 계산·검증 복잡도**를 이유로 설명하는 것이 적절하다. 시간 지연이나 렌즈 효과가 있다는 이유로 관측이 무의미해지는 것은 아니다.

원거리에서 낙하 물체가 영원히 선명하게 정지해 보이는 것도 아니며, 적색편이와 감광으로 관측하기 어려워진다. 좌표에 따른 기술 차이와 사건의 지평선이라는 인과적 경계도 구별해야 한다.

근거: [NASA 블랙홀 FAQ](https://science.nasa.gov/apod/frequently-asked-questions-faqs-on-black-holes/).

## 14. 제안하는 제품 설명

> 공개 천체력과 실제 SPHEREx 관측을 연결해, 1,000 AU를 주요 탐색 범위로 태양계 외곽 천체의 분류와 미발견 행성 가설을 비교하고 검토 근거를 재현하는 도구.

이 프로젝트의 강점은 **어떤 가설이 어떤 실제 관측과 맞고 무엇이 아직 모르는 부분인지를 사용자가 추적할 수 있게 하는 것**에 둔다. 완벽한 우주 복제나 발견 성공을 구현 완료로 주장하지 않는다.
