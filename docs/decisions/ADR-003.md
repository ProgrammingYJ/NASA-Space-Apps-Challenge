# ADR-003 — Node.js만 있는 서버의 검증된 관측 캐시 실행

상태: DEV-012 구현 중. 사용자 제공 운영 제약은 **서버에서 Node.js만 실행 가능**이다. 기존 Python/FITS 과학 코드를 제거하거나 기존 관측·근거·Git을 덮어쓰지 않는다.

실행 진입점은 프로젝트 루트 `app.js`, 시작 명령은 `node app.js`로 한다. Node HTTP 서버는 빌드된 `web/dist`, 파일 기반 근거/작업 상태와 실제 자료 snapshot을 제공한다. 운영 중 Python 프로세스를 시작하거나 별도 Python 서버를 필수로 요구하지 않는다. 선택적 기존 Python API/과학 코드는 개발·재검산 경로로 보존한다.

현재 비교 API는 ε Indi B S01/S02와 명왕성 S12/S14 두 쌍만 받으며 사용자가 ROI·측정법을 임의 변경하는 API는 없다. 빌드 시 기존 과학 함수로 실제 FITS에서 두 비교를 새로 계산하고, 원본/보정·설정·알고리즘·결과 해시와 함께 파생 캐시에 담는다. Node는 정본 캐시와 현재 원본의 무결성이 맞을 때만 이 결과를 재사용한다. 이 동작을 새로운 런타임 FITS 분석이나 새 검출로 표시하지 않는다. 원본이 달라지거나 캐시가 없으면 실패/재계산 필요이며 과거 검사 숫자나 합성 영상을 채우지 않는다.

카탈로그 snapshot도 기존 실제 reader의 출력과 출처를 보존한다. 질량 가정·천체력 표시 보간·장기 Kepler 계산은 요청 값에 대응하는 일반 수식을 Node로 옮기고 Python/브라우저 참조와 독립 대조한다. 특정 테스트 연도/밀도의 출력을 하드코딩하지 않는다. Node API만 상태의 작성자이고 worker thread는 해시/캐시 읽기 결과를 보고한다. 원자적 저장·한 인스턴스 잠금·재시작 interrupted·8MB/스키마/경로 검사를 유지한다.

이전 Python 근거는 정본 비교의 구조와 기존 Python 내용 SHA를 함께 대조해 호환한다. JSON 숫자의 `1.0`/`1` 직렬화 차이가 관측값·결과 ID를 바꾸거나 변조 검사를 생략하는 이유가 되지 않는다. 실제 εB/Pluto 근거를 양쪽 런타임과 새 세션/재시작에서 검증한 뒤 완료로 기록한다.

Node에서 새 좌표/관측 원본을 즉시 내려받아 분석하거나 임의 새 FITS를 처리하는 기능은 제공하지 않는다. 이는 기존에 미구현이던 자유좌표/정밀측정 기능과 구분한다. 구현/검사/배포의 최신 상태는 FSD, 자료 전수 목록과 파생 관계는 Data_Spec에 유지한다.
