# ADR-001 · 첫 관측 경로의 파일 저장과 단일 과학 worker

> 문서 현행화 정본(2026-11-15): 사용자 보조 PDF 철회에 따라 검증된 **v0.17.3을 현재 운영으로 재활성화했다.** 승인 닉네임·테스터6명/영어 기본값은 유지하며 보조 고지 PDF는 공개 동선에서 제거했다. [철회·복귀 정본](../releases/notice-withdrawal-20261115.json)을 따른다. v0.17.4의 수치·SHA·검증은 철회된 과거 이력이며 현재 배포가 아니다. Git 결과는 정본에서 확인하고 아래 날짜별 기록은 당시 이력으로 보존한다.

> 현행 연결(2026-11-15): 이 문서는 작성 당시 결정·검토 기록이다. 당시의 “미구현/예정”은 현재 상태 판정이 아니다. 현재 태양계1000AU·제9행성/실관측 범위와 Node 전용 실행, 실제 궤도 유사도 TOP5·PC Chrome 권장·모바일 안내, 새 EC2 검증은 [FSD31~34](../../FSD.md)와 v0.17.3 재활성화의 [철회·복귀 정본](../releases/notice-withdrawal-20261115.json)을 따른다. v0.17.4는 철회된 과거 검증이며 [v0.17.0](../releases/v0.17.0.json)은10기능경로의 당시 검증 스냅샷이다. 외부 자료를 이번 문서 정리에서 다시 조회한 것으로 주장하지 않는다.

상태: 구현 · 작업 DEV-001 · 2026-11-14 KST · 결정 범위: FSD의 파일 우선 구조 내 세부 구현.

API 하나가 OS 파일 잠금으로 상태 디렉터리를 독점하고 RLock으로 모든 job/evidence/result 갱신을 직렬화한다. Python spawn worker 하나와 양방향 Pipe로 입력·attempt·결과·heartbeat를 교환한다. worker는 영속 상태를 쓰지 않는다. API는 임시파일 fsync→원자적 replace→완전성 검증 후 succeeded를 쓴다. 두 번째 API 작성자는 시작을 거부한다.

기존 Python 과학 라이브러리를 직접 호출하는 API thread 방식과 별도 worker 방식을 비교했다. 별도 프로세스는 초기화/종료 처리가 더 필요하지만 이벤트 루프와 원본 처리를 분리하고, 취소·중단을 명시할 수 있어 기존 계약에 맞는다. 외부 큐/DB는 첫 근거 저장의 선행 조건으로 추가하지 않았다.

worker 초기화 때 관측 목록을 한 번 산출하고 API 메모리에 보관한다. 비교는 매번 실제 입력의 전체 SHA를 확인하고 결과 내용 해시를 ID에 반영한다. 취소 요청은 실행 중 즉시 종료로 가장하지 않고 결과 수신 안전 지점에서 폐기한다. 대기열은 최대8개다. 복원은 로컬 결과 정본과 원본/보정의 현재 SHA·바이트를 모두 확인하며 누락/변경 시 재계산 필요로 반환한다.

재시작은 이전 PID/생성시각/프로세스 식별을 확인하고 이전 worker가 종료된 뒤 미완료를 interrupted로 바꾼다. 종료 처리와 재시작 검사는 tests/test_api.py 및 tests/test_restore_edges.py에 연결한다. 정밀 측정과 이후3D는 이 결정의 구현 완료 범위에 포함하지 않는다. 상세 필드/상태와 최신 구현 현황은 FSD11–13/20절이 정본이다.

되돌리기: API 종료→자식 종료 확인→이전 코드와 호환되는 별도 상태 디렉터리로 실행한다. 기존 var와 원본을 초기화/덮어쓰지 않는다.
